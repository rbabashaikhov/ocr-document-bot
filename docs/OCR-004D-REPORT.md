# OCR-004D — повышение надёжности Table Grid Detector

## Границы работы

Доработан только изолированный исследовательский модуль `research/table_grid.py`. OCR Engine, Yandex mapper, Document Model и DOCX Renderer не импортируют его и не изменялись. OCR API-вызовы не выполнялись.

Исходные изображения, JSON fixtures и визуальные результаты остаются локальными и исключены из Git: `tests/samples/`, `fixtures/vision/` и `artifacts/ocr-004d/`.

## Изменения алгоритма

### Deskew

Перед выделением линий используется Canny + `HoughLinesP`. Медиана почти горизонтальных сегментов определяет малый угол скана; коррекция применяется только при двух или более согласованных сегментах и угле не более 8°. Поворот выполняется на белом фоне. Центры OCR bounding boxes преобразуются той же affine-матрицей, поэтому сопоставление идёт в одной системе координат с сеткой.

Предел в 8° — намеренно консервативная граница малого перекоса, не замена перспективному выравниванию. Для крупных поворотов и перспективы результат остаётся без автоматической таблицы.

### Разделение и оценка сеток

После Otsu-бинаризации длинные относительные морфологические ядра выделяют горизонтальные и вертикальные правила. Связные компоненты объединённой маски линий рассматриваются отдельно, поэтому на одной странице могут быть обнаружены несколько независимых таблиц.

Для каждого кандидата вычисляются диагностические признаки:

| Признак | Назначение |
| --- | --- |
| `outer_rule_coverage` | минимальная доля видимого материала на одной из четырёх внешних границ |
| `intersection_ratio` | доля подтверждённых пересечений среди узлов найденных рядов и колонок |
| `consistent_cells` | каждая минимальная позиция сетки покрыта ровно одной итоговой ячейкой |

Это геометрические показатели, **не вероятности и не ML confidence**.

Решение:

- `detected`: не менее трёх линий каждого направления, `outer_rule_coverage ≥ 0.75`, `intersection_ratio ≥ 0.70`, непротиворечивые ячейки;
- `candidate`: сетка связна (`intersection_ratio ≥ 0.70`) и имеет заметную внешнюю границу (`outer_rule_coverage ≥ 0.25`), но не проходит строгий критерий `detected`;
- `not_detected`: нет компонента, удовлетворяющего даже критерию `candidate`.

Минимальные размеры компонента (60×40 px) и морфологические ядра имеют также относительную составляющую, зависящую от изображения. Числа выбраны как защитные условия геометрии, а не под координаты OCR-002B; их необходимо валидировать на расширенном наборе данных до product-интеграции.

### Ячейки, объединения и текст

Базовые ячейки строятся только между найденными линиями. Соседние позиции объединяются исключительно там, где внутреннее правило действительно отсутствует в маске; создание недостающих линий не выполняется. Для каждого объединения проверяется прямоугольность, а для всей таблицы — покрытие минимальной сетки без пропусков и перекрытий.

Текст распределяется по центру OCR bounding box только у `detected`. У `candidate` массив `mapped_block_indexes` всегда пуст, а все блоки остаются `unmapped`: будущий pipeline обязан сохранить исходные Paragraph/`table_candidate`, не теряя текст.

## Ограничения и рекомендация

- Коррекция учитывает лишь небольшой поворот, не перспективное искажение, изгиб страницы или сильный шум.
- Граница, потерянная при сканировании, может выглядеть как объединение; строгая проверка снижает риск, но не доказывает смысловое объединение.
- Сопоставление по центру bounding box не разрешает блок, реально пересекающий две ячейки.
- Таблицы без видимых правил сознательно не восстанавливаются данным подходом.

Рекомендация: **можно готовить ограниченную интеграцию только за feature flag и только для `detected`**, сохраняя исходные блоки до проверки отсутствия потерь/дублей. `candidate` должен попадать исключительно в диагностический или ручной review-путь. До включения по умолчанию нужны эталонный набор анонимизированных таблиц, метрики ложных срабатываний и потерь текста, deskew для перспективы и политика координат для многостраничного документа.

## Реализация

### Модуль и флаг

Проверенный алгоритм перенесён в production-модуль `ocr_document_bot.document_model.visual_table_detector`. Исследовательская версия в `research/table_grid.py` сохранена неизменённой как диагностический прототип.

`opencv-python-headless` перенесён в обычные runtime-зависимости, поскольку visual path теперь может быть включён в сервисе. Новая конфигурация:

```dotenv
OCR_ENABLE_VISUAL_TABLE_DETECTION=false
```

По умолчанию feature flag выключен. Значения `1`, `true`, `yes`, `on` включают его. Mapper также принимает необязательный явный параметр `enable_visual_table_detection` для контролируемых локальных тестов.

### Порядок принятия решения

1. Если Vision вернул нативный `tables[]`, используется только он; visual и старый block-layout детектор не запускаются.
2. Если нативных таблиц нет, flag включён и передан локальный source image, запускается visual detector.
3. Только `detected` превращается в независимый `Document Model Table`.
4. При `candidate` и `not_detected` visual путь не удаляет ни одного блока; затем выполняется прежнее поведение `LayoutTableDetector`.
5. Если visual table подтверждена, её блоки исключаются из Paragraph/Heading, а fallback block-layout detector на этой странице не запускается. Так исключено двойное восстановление.

### Координаты и текст

Visual detector получает центры OCR bounding boxes, масштабирует их между размерами annotation и исходного изображения, затем применяет ту же deskew affine-матрицу, что и к изображению. Найденные границы и ячейки масштабируются обратно в координаты независимой Document Model.

Для подтверждённой таблицы сохраняются строки, столбцы, пустые ячейки, `row_span`, `column_span`, geometry и provenance. Все связанные OCR-блоки удаляются из обычного потока ровно один раз. При нескольких блоках в одной ячейке их текст объединяется переводом строки. Reading Order Resolver затем размещает таблицу среди оставшихся абзацев по geometry.

## Ограничения и рекомендация

- Путь требует локальный исходный image для каждого OCR response; JSON сам по себе не даёт пиксельных линий.
- Поддерживается малый deskew, но не перспектива, изгиб листа или тяжёлый шум.
- Только таблицы с убедительными видимыми правилами становятся `detected`; нерешённые случаи намеренно остаются текстом или существующим `table_candidate`.
- Результат не корректирует текст Vision и не воспроизводит исходный дизайн.

Рекомендация: оставить flag выключенным по умолчанию до накопления анонимизированного регрессионного набора и метрик ложных срабатываний. Ограниченное включение допустимо для image-first обработки с feature flag и журналированием статусов `detected`/`candidate`/`not_detected`.
